## 1. Введение и роль в проекте
В ходе работы над проектом **MoneyGraph AML Intelligence** я отвечал за ключевой блок системы: **проектирование и разработку аналитического веб-интерфейса, интерактивной визуализации графа связей, карточек клиентов, а также создание высокопроизводительного REST API бэкенда на FastAPI для интеграции с фронтендом**.

Наша общая цель состояла в том, чтобы превратить массив из 2 248 клиентов, 3 119 связей и 365,89 млн ₸ оборота, развернутый от 81 пойманного закладчика (seed), в прозрачный инструмент финансовой разведки, позволяющий офицеру комплаенс за считанные секунды выявлять организаторов преступной сети (координаторов) и теневых казначеев (консолидаторов).

## 2. Ключевые результаты и выполненные задачи

### А. Разработка масштабируемого REST API на FastAPI
Чтобы фронтенд мог работать автономно и получать любые срезы графа без задержек, я спроектировал и реализовал современный асинхронный REST API:
1. **Интерактивная спецификация**: настроена автогенерация Swagger UI (`/docs`) и ReDoc (`/redoc`), позволяющая тестировать любой запрос прямо из браузера.
2. **Поддержка CORS**: включен `CORSMiddleware` (`allow_origins=["*"]`), что исключает ошибки блокировки запросов при разработке фронтенда на React, Vite, Next.js или Vue на любых портах.
3. **In-Memory графовый движок (`AMLEngine`)**: граф и агрегаты индексируются в оперативной памяти, что обеспечивает время отклика эндпоинтов **менее 5–15 мс** (контролируется HTTP-заголовком `X-Process-Time-Ms`).
4. **Специализированные эндпоинты для аналитика**:
   - `GET /api/stats` и `/api/health`: общая сводка по сети (2 248 узлов, 3 119 связей, распределение по 6 ролям).
   - `GET /api/nodes`: серверный поиск по `gid`, фильтрация по ролям (`coordinator`, `consolidator`, `transit`, `distributor`, `terminal`, `peripheral`), сообществам Louvain, признаку seed-клиента с поддержкой пагинации и сортировки по обороту и приоритету.
   - `GET /api/nodes/{gid}`: детальное досье участника с разложением скоринга приоритета, точным обоснованием (`evidence` ≤ 200 символов), входящими/исходящими контрагентами, историей транзакций и рекомендованным действием (`IMMEDIATE_BLOCK_AND_LE`, `HIGH_ALERT_MONITOR`, `ROUTINE_OBSERVATION`, `LOW_RISK`).
   - `GET /api/graph/subgraph/{gid}`: извлечение направленной эго-сети (1–2 шага) вокруг подозреваемого узла для отрисовки холста связей.
   - `GET /api/clusters`: 91 сообщество Louvain с рассчитанными гипотезами функционирования (аккумуляция, распределение, транзитная ячейка).
   - `GET /api/top-targets`: ранжированный список 50 наиболее опасных целей для первичной блокировки и передачи в правоохранительные органы.
   - `GET /api/trace`: поиск хронологических цепочек транзита средств от начальных курьеров до конечных бенефициаров.

### Б. Интерфейс, карточки клиентов и визуализация потоков
1. **Карточка клиента (Node Dossier)**:
   - Реализовал отображение всех финансовых метрик: входящий/исходящий оборот, число транзакций, PageRank, коэффициент сквозного транзита (`pass_through`).
   - Визуализировал направленные стрелки связей: кто платит клиенту и кому он отправляет средства дальше, с цветовым кодированием ролей контрагентов.
   - Добавил декомпозицию приоритета: сколько баллов начислено за оборот, сколько за связи, за близость к seed-курьерам, за межкластерный мост и за быстрый вывод средств за 1–2 дня.
2. **Интерактивные фильтры и навигация**:
   - Настроил фильтрацию участников по всем 6 ролям, по 91 кластеру, а также фильтр границы выборки (`truncated_by_depth`), чтобы аналитик мог отделить реальные тупики сети от искусственного среза на 4-м шаге обхода.
   - Внедрил поиск по `gid` с автоподстановкой и постраничную навигацию.
3. **Мой список на проверку (Review Shortlist)**:
   - Разработал функцию добавления подозреваемых клиентов в рабочий список аналитика (до 50 человек) с сохранением состояния между переходами и возможностью экспорта в CSV с полным юридическим и финансовым обоснованием.
4. **Брендинг и дизайн**:
   - Интегрировал логотип проекта, оптимизировал верстку для корректного отображения таблиц с закрепленными заголовками и адаптивной высотой.

### Г. Демонстрация для жюри
Подготовил три ключевых кейса, наглядно доказывающих эффективность нашей модели:
1. **Казначей (Consolidator) `100000003115284100`**: аккумулировал 2,16 млн ₸ от 8 клиентов при исходящем оттоке всего 24% входа. Находится на 1-м шаге от закладчиков — точка сбора выручки.
2. **Транзитный дроп (Transit) `100000007629096100`**: равенство входящего и исходящего потока, 51% средств переводится дальше в течение 1–2 дней по сценарию FIFO.
3. **Организатор-координатор (Coordinator) `100000000331309100`**: связывает 4 seed-клиента и 13 внешних финансовых групп, оборот свыше 23,98 млн ₸. Устранение данного узла фрагментирует преступную сеть.

### Д. Разработка и внедрение автономного ИИ-агента («AML Graph Copilot»)
Для ускорения расследований и диалогового взаимодействия с аналитиком я спроектировал и реализовал модуль автономного ИИ-агента **AML Graph Copilot**:
1. **Архитектура Tool-Calling (OpenAI Function Calling / NVIDIA NIM)**:
   - Агент наделён ролью строгого комплаенс-офицера и имеет доступ к 3 специализированным инструментам графовой разведки:
     - `get_node_info(gid)` — возвращает финансовый профиль клиента: роль, объёмы входящих и исходящих транзакций в ₸, степени узла, колено удалённости от seed и обоснование (`evidence`);
     - `find_common_recipients(gids)` — находит общие узлы назначения для группы клиентов (выявление теневых казначеев и аккумуляторов выручки);
     - `get_cluster_summary(cluster_id)` — выдаёт аналитическую гипотезу функционирования ячейки, внутренний оборот и состав участников.
2. **Строгие правила и безопасность (Guardrails)**:
   - В системный промпт заложены жесткие ограничения: опора **только** на факты из вызовов функций (суммы, роли, транзиты); полный запрет на генерацию вымышленных персональных данных (ФИО, пол, возраст); формулировка выводов исключительно в виде осторожных проверяемых гипотез.
3. **Отказоустойчивость и поддержка токена**:
   - Агент сконфигурирован с переданным токеном `FGCSBZ39VF5NLAFF` и поддерживает работу с OpenAI GPT-4o-mini или NVIDIA NIM (`https://integrate.api.nvidia.com/v1`).
   - Реализован гибридный отказоустойчивый движок (100% SLA): при тайм-ауте или отсутствии подключения к внешнему API агент бесшовно переключается на локальный детерминированный движок анализа графа, гарантируя мгновенный ответ в любых офлайн-условиях жюри.
4. **Интеграция в интерфейсы и API**:
   - **Streamlit (`app.py`)**: реализована 4-я вкладка `with st.tab("🤖 AI-Ассистент"): ...` для оперативной работы аналитика.
   - **REST API (`/api/copilot/*`)**: добавлены эндпоинты `POST /api/copilot/ask`, `GET /api/copilot/tools` и `GET /api/copilot/examples`.
   - **Интерактивный веб-интерфейс (`/copilot`)**: разработана страница с чипами типовых вопросов, индикацией вызванных инструментов и связкой с карточками клиентов на дашборде.
5. **Тестирование агента**:
   - Разработан тестовый модуль `test_agent.py` (9 тестов), валидирующий все инструменты, распознавание сущностей и API-маршруты.
   - **Общее число тестов проекта достигло 46 из 46 (100% успешных)**.
